# NAS 모드 정보 복구 대조표

기준: v2.0.34의 실제 세 카드와 현재 NAS 데이터 경로. 2026-10-16 KST, 문서 v3.7. 현재 설치·공개 앱은 2.1.3 / 202610161323이다. 세 카드 복구의 최초 공개 기준은 2.1.2 / 202610161301이다.

Codex·Claude·Gemini 세 카드의 기존 디자인과 정보 밀도를 유지하고 데이터 출처를 NAS로 연결한다. 소스에 표시 경로가 생긴 것과 운영 설치 후 값이 확인된 것은 구분한다. 선택 계정 바인딩·이력 분리·호스트 진단 문구 제거를 반영한 앱 2.1.2는 release 빌드·기존 Developer ID 서명·교체 설치·재실행까지 확인했다. 실제 AppKit의 세 카드 렌더와 관련 대상 테스트 7개가 통과했다. 해당 렌더는 비식별 fixture다. NAS 배포 후 설치 앱의 실제 `nasFourServiceCacheV1`에서도 NAS 출처와 네 서비스의 최신 정상 응답, 요금제·초기화권·선택 계정 바인딩을 확인했다. 실제 수신 캐시 확인과 창 픽셀 렌더 확인은 서로 다른 증거로 구분한다.

## 새로 요청한 Claude 리셋권

일반 usage/profile 응답만 확인했을 때는 수집 경로가 미확보였다. 이후 공식 Claude Code 2.1.288 바이너리에서 `GET /api/oauth/usage?cedar_ember=1&skip_spend=1` 조회 경로를 확인했고, NAS의 기존 인증으로 HTTP 200과 `grants: []`를 실제 확인했다. 빈 grants는 이 조회 시점의 잔여 리셋권 0개라는 확인된 결과다. 이전의 “수집 경로 미확보” 결론을 이 증거로 정정한다. 이 경로는 공식 CLI에서 발견한 실제 사용 경로이며 공개적으로 안정성을 보장한 API 계약이라고 확대하지 않는다.

새 NAS 계약은 선택적 `claude_details.limit_resets`의 `remaining_count`(0 이상 JS 안전 정수), `usable_now`(불리언 또는 null), `expires_at`(Unix 초 또는 null)이다. 개수는 공식 UI처럼 `grants[].resets_left`의 합계를 쓰며 지금 사용할 수 있는지는 별도다. 양수가 있어도 대기 상태일 수 있다. 앱은 기존 Claude 카드 행에 `리셋권`을 추가하여 확인된 0은 `0개`, 양수는 `N개`와 확인된 사용 가능/대기를 짧게 표시한다. 누락·잘못된 타입·범위 초과·오래되거나 실패한 조회는 `확인 불가`로 표시하며 기존 정상 한도·요금제·추가 사용량을 지우지 않는다. 만료 시각은 캐시와 공유 JSON에 보존하되 카드 과밀을 막기 위해 별도 행을 추가하지 않는다.

2.1.3의 파서·NAS 캐시·snapshot·공유 JSON·카드 표시를 구현하고 0/양수/미확인/타입 오류/범위 초과/직렬화/계정 외 서비스 격리와 기존 회귀를 포함한 관련 대상 테스트 71개를 통과했다. 독립 소스 검토에서 P1/P2 문제 없음, Universal 빌드·기존 서명·공증·정식 공개·교체 설치·재실행을 확인했다. 공개 파일을 다시 내려받아 release.json·DMG SHA-256·업데이트 ZIP Ed25519 서명과 설치본 실행 파일 일치도 확인했다. NAS 0.22.1 / 202610161323 운영 배포 후 정상 수집 주기가 지난 13:35 KST에 Foundation UserDefaults의 실제 설치 앱 `nasFourServiceCacheV1`을 읽어 `source=nas`·`ok=true`·`stale=false`·`fetched_at=1792125199` 및 `limit_resets={remaining_count:0, usable_now:false, expires_at:null}`을 확인했다. NAS SSH snapshot의 값과 수집 시각도 일치했다. 직접 GET 결과만으로 앱 수신을 추정하지 않았고, 캐시 값 주입이나 수집 시각 조작 없이 정상 TTL 수집 결과를 확인했다. 리셋권을 자동 소비하는 기능은 구현하지 않는다. Local 수집에 리셋권 조회가 없다면 그 값을 NAS에서 빌려 오지 않고 확인 불가로 표시한다.

## 기존 카드와 별도로 다룰 정보

Claude 모델명·컨텍스트·작업 비용은 statusLine/공유 데이터 모델에 존재하지만 v2.0.34 claudeColumn의 실제 카드 행에는 사용되지 않았다. 모델에 필드가 있다는 이유로 화면 회귀라고 단정하지 않는다. NAS 작업의 해당 정보를 추가하려면 NAS statusLine 출처와 작업 ID 대응이 필요하며 Mac 작업 정보를 NAS 작업처럼 보이지 않는다.

Gemini 온라인 웹 한도·AI 크레딧은 v2.0.34의 CLI 공유 데이터와 별도 브라우저 경로에 있으며 원래 세 카드의 표시 항목과 구분한다. NAS에 없는 Mac 브라우저 세션 데이터를 자동 전송하지 않는다.

## 현재 소스의 선택 계정 바인딩

내부 목록은 `accounts_v3`의 본계정 하나와 보조계정 N개다. 과거 `account1/account2`는 호환 기본값이며 개수 제한이 아니다. 기존 네 서비스 API(`codex/claude/gemini/gemini2`)를 유지하면서 선택된 보조계정은 `gemini2` projection의 `actual_account_ref`로 구별한다. CCMB에 보조계정 카드를 나열하지 않는다.

NAS 모드의 Gemini 카드는 `host_id=nas` 범위 하나만 따른다. Mac 호스트 이벤트가 NAS 카드를 바꾸지 않는다. `selected_account_id`, `selected_role`, `selected_service`, `selection_generation`, `observed_at`으로 idle의 마지막 선택을 보존하고 실제 `execution_account`와 구분한다. `return_state=confirmed`는 본계정 복귀 확인이며 보조계정 선택 근거가 아니다. 자동 전환 꺼짐이나 명시 선택 미확인은 본계정 표시 기본값으로 처리하되 실행 중이라는 주장으로 쓰지 않는다.

선택 계정과 서비스의 실제 계정 ID가 다르면 해당 숫자를 표시하지 않는다. `history_identity`로 해당 계정의 그래프만 사용한다. 계정 변경 뒤 실패한 수집에 이전 계정의 last-good 값을 빌려 쓰지 않는다. 다른 서비스의 정상 값은 유지한다. 이력 수집기는 기존 본계정 이력과 레거시 세대 식별자의 연속성을 보존하며 계정 변경으로 가짜 소비량을 만들지 않는다.

기존 세 카드 아래의 출처·조회 시각·오래됨·오류는 유지하되 Gemini에 모든 호스트의 대기·복귀·변경 내역을 늘어놓아 카드 전체 높이를 키우지 않는다. 전체 동적 계정 상태는 NAS에서 확인할 데이터이며 공개 허용 필드만 사용한다. 최초 운영 NAS 서버 현황 0.22.0 / 202610161301에서 두 계정의 정상 사용 가능 상태와 Mac·NAS 선택 상태가 표시되는 것을 확인했다. 이 화면 확인은 API 필드 존재 여부와 별도로 수행했다.

## 폴더 방식 운영 실증

Mac은 공식 Antigravity 1.3.6의 자식 프로세스에만 Keychain 및 본계정 인증 경로 접근을 차단하여 전용 HOME의 파일 인증으로 실제 신원·사용량·읽기·쓰기·명령 작업을 확인했다. 보조계정 만료 메타데이터를 바꾼 통제 갱신을 먼저 확인했다. 이후 VM을 삭제한 상태에서 실제 만료 시각 13:09:56 KST가 지난 뒤 공식 CLI의 토큰 변경·만료 시각 증가·동일 계정 신원·후속 usage SUCCESS까지 확인하여 자연 만료 후 갱신도 별도로 검증했다. 통제 갱신과 자연 만료 갱신을 혼동하지 않는다. NAS는 공식 1.3.5의 별도 영속 HOME에서 자연 만료 401 이후 공식 갱신·신원·사용량을 확인했다. 본계정 로그인은 유지했다.

NAS의 터미널 user namespace는 실제로 작동하지 않았다. 파일 도구와 작업별 명시된 정확한 명령의 임시 허용을 구분하고 전역 샌드박스 해제로 대신하지 않는다. 이 차이는 사용량 카드의 성공을 실제 모든 작업 능력의 성공으로 확대하지 않기 위해 기록한다.

새 런타임은 Mac과 NAS에 운영 설치했으며 양쪽 자동 전환을 켰다. 본계정 원본 한도 1% 이하 또는 검증된 소진 시 유효 보조계정을 선택하고, 실제 회복 재조회 후 다음 새 작업부터 본계정으로 복귀한다. 시작한 작업은 자동 재실행하지 않는다. 실제 계정과 작업을 이용한 통제된 저한도·회복 조건에서 Mac/NAS의 본계정 → 보조계정 → 본계정 작업이 통과했다. 실제 본계정 한도를 소진시켰다는 뜻은 아니다.

Mac의 실제 Codex Gemini 래퍼 운영 호출도 통과했다. NAS는 ai_team 경로의 pwd·파일 작업, 선택 계정 전용 임시 명령 허용, 종료 후 임시 허용 회수와 settings 원복을 확인했다. 본계정 settings 해시는 작업 전후 동일했다. 이는 본계정 로그인 파일을 교체하거나 로그아웃하지 않고 확인한 결과다.

안전한 인증 이전과 폴더 경로 작업 확인 후 이번 기능 전용 VM 두 개를 실제 삭제했다. Mac 3,185,369,088바이트, NAS 1,549,905,920바이트의 할당 공간을 회수했다. 별도 영속 프로필과 공유 CLI를 사용하는 현재 경로에 VM이 필요하지 않다. 이 수치는 가상 디스크의 논리 최대 크기가 아닌 삭제 전 할당량이다.

이 앱 배포는 사용량 카드 표시를 복원하는 변경이다. 앱 설치 자체가 다른 기기의 서버 인증이나 계정 전환 설정을 자동으로 마련한다는 뜻은 아니다. 해당 환경의 폴더 프로필·컨트롤러·인증·활성화가 별도로 준비되어야 하며, 위 운영 실증은 현재 Mac과 NAS에 준비된 환경에 한정한다. 새 NAS API 배포 후 설치 앱의 실제 저장 캐시에서 `source=nas`, 네 서비스 모두 `ok=true`·`stale=false`, Codex Pro·초기화권 3개, Claude Max 5×·추가 사용량 비활성, Gemini `account1/account2` 실제 계정 참조를 확인했다. `host_status`는 자동 전환 켜짐이며 Mac·NAS 모두 idle·선택 `account1`이었다. 이 확인은 앱의 실제 수신 상태이며 운영 창 전체의 픽셀 대조로 확대하지 않는다.

여러 보조계정 선택 소스와 실제 인증은 구분한다. 현재 실제 Gemini 보조계정은 하나이며 추가 실계정 인증을 확인했다고 보고하지 않는다. Claude는 향후 별도 provider adapter와 공식 `CLAUDE_CONFIG_DIR` 경로로 확장할 대상이다. 현재 Claude 보조계정 인증·자동 전환을 구현한 것은 아니다.

## 최종 완료 증거와 제한

- 앱 2.1.3 / 202610161323을 Universal 빌드·Developer ID 서명·공증·교체 설치·재실행했다. 비식별 실제 AppKit 렌더로 세 카드와 호스트 진단 문구 제거를 확인했고 관련 대상 테스트 7개가 통과했다.
- NAS 서버 현황에서 두 계정과 호스트별 선택을 확인했고, 후속 NAS 0.22.1 / 202610161323 배포 후 설치 앱의 실제 수신 캐시와 NAS SSH snapshot을 대조했다. 네 서비스의 정상·최신 수신, Codex Pro·초기화권 3개, Claude Max 5×·추가 사용량 비활성에 더해 Claude 리셋권 0개가 정상 수집되어 전달됨을 확인했다.
